# 全局分页统一修复清单

## 1. 目标

- 统一前后端分页行为，避免出现“页面设置为 10 条/页，但实际展示超过 10 条”或“第 2 页为空/数据异常”的问题。
- 保留订阅限制 `query_limit` 的能力，同时允许前端传入更小的 `page_size` 生效。
- 以“统一规则 + 分批修复”的方式推进，避免一次性全仓重构带来的高风险。

## 2. 当前结论

### 2.1 后端问题不是采购模块独有

当前项目后端存在两类分页问题：

1. `query_limit` 被 helper 优先直接返回，导致前端传入更小的 `page_size` 不生效。
2. helper 根本不读取 `page_size`，导致前端页大小设置完全被忽略。

### 2.2 前端也存在分页未统一的问题

## 3. 统一规则

### 3.1 后端统一规则

所有分页 helper 统一为以下规则：

```python
effective_page_size = min(front_page_size, query_limit)
```

执行细则：

1. 优先读取请求中的 `page_size`。
2. 若存在订阅限制 `query_limit`，则返回 `min(page_size, query_limit)`。
3. 若未传 `page_size`，则回退到 `query_limit` 或默认值。
4. `page_size` 仍需保留合法范围校验，如 `1 <= page_size <= 100`。

### 3.2 前端统一规则

前端列表分为两种模式，不允许混用：

1. 服务端分页：接口已返回当前页数据，前端不可再次 `slice`。
2. 本地分页：接口返回全量数据，前端才允许 `slice`。

建议为 [ListTemplate.vue](file:///d:/WMS/Warehouse-Management/wms-vue3/src/views/common/ListTemplate.vue) 增加一个显式模式开关，例如：

- `paginationMode: 'server' | 'client'`

默认建议为：

- 业务主列表默认 `server`
- 仅 mock/fallback/树节点本地缓存列表使用 `client`

## 4. 修复范围建议

### 4.1 本轮建议纳入

- `nuomi_wms/app/api/v1/endpoints` 下所有存在分页 helper 的业务文件
- `wms-vue3/src/views/common/ListTemplate.vue`
- `wms-vue3` 中高风险分页页面

### 4.2 本轮不建议纳入

- `admin-web`
- 所有纯本地静态表格页面
- 一次性全量替换所有页面分页实现

原因：

1. `admin-web` 分页实现独立，接口模型与 `wms-vue3` 不同。
2. 一次性全量改造成本高、联动范围大、回归风险高。
3. 当前最优策略是先统一能力，再分批迁移页面。

## 6. 验收标准

### 6.1 后端验收

- 任一分页接口在传入 `page_size=10` 时，返回条数不超过 `10`。
- 若订阅限制为 `15`，前端传 `10` 时返回 `10`，传 `20` 时返回 `15`。
- 所有分页 helper 行为一致，不再出现模块间逻辑差异。

### 6.2 前端验收

- 服务端分页页面切换 `10/20/50` 条/页时，表格展示条数与接口返回一致。
- 第 2 页及以后不出现空表、重复数据、条数异常。
- 本地分页页面仍能正常切片，不受服务端分页模式改动影响。

## 8. 风险提示

### 8.1 不建议直接全量重构

原因：

1. 当前分页问题横跨后端 helper、前端组件、页面请求参数、响应解析四层。
2. 许多页面存在历史兼容逻辑，直接全量替换容易引发回归。
3. 更适合按批次推进，每批可独立验证。

### 8.2 建议的实施策略

- 采用“先规则统一，再页面迁移”的方式推进。
- 每修完一个后端文件，立即回归对应模块分页页面。
- `ListTemplate.vue` 改动后，优先验证第 2 页及以上分页页面。
