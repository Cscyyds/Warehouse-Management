## 重点观察项(实测与预期不符,按影响排序)

> 2026-09-28 下午修复批次:以下 1~5 已修复并回归(见 Page_Agent_Search.md §11.5.15 第六节);
> 表格中对应条目的"⚠️实测"为修复前行为,复测应以本节"修复后"为准。

1. **#74 系统管理 → 岗位管理**:目录无页面声明"系统管理",L3 模糊通道(编辑距离 2)抢 confident,区块兜底永不执行。✅已修复:区块标签直呼(候选全为模糊命中时)回落区块主页+追问,现跳人事资料管理;财务管理/产品管理等同族一并修复。
2. **#57 查看库存的出库记录 → warehouse.stock 查询**:excludedIntents ×0.3 惩罚把目录 top 压到 151(<250),`prefersOtherPage` 失去否决权,业务意图正则层绕过排除词。✅已修复:排除词硬否决,查询动作一律拦截;终点行为按产品口径"不拒绝用户"——打开产品库存 + 追问"如果这不是你要找的页面请告诉我"。
3. **#78 查一下某个产品的库存数量 → product.info**:intentExample"查询某个产品的库存数量"声明在 warehouse.stock,但 product.info 的"查一下某个产品"(intentExample,383 分)压过"库存"keyword(360 分)。✅已修复:warehouse.stock keywords 补「查一下某个产品的库存数量」(630 分),现确定性委派 inventory.search。
4. **#58 销售订单的出库商品明细 → sales.order**:两边候选都带排除词,幸存者反而跳转。✅已修复:与 #2 同根,现跳销售订单(用户点名页面)+ 追问确认,不再静默落地;查询动作仍被拦截。
5. **#36 开一张采购入库单 → 查询**:createPattern 未覆盖"开一张/开个",且业务意图层抢先编译成查询 Action。✅已修复:createPattern 增补 `开一[张个]` + 建单意图优先于查询意图,现进入采购入库单新增页(mode=create)。
6. **#61 昨天卖了多少货 → 闲聊**:"卖了多少"前无"产品/商品/货品"字样时聚合口语正则不触发,同族话术行为不一致。✅已修复:sales.report.order-detail keywords 补「卖了多少货」,现确定性委派销售订单明细查询。
