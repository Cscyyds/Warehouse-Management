# 搜索弹窗分页统一规范

## 1. 目标

- 统一 `SelectDialog` / `Picker` 类搜索弹窗的远程分页行为，避免出现“首次打开空表”“依赖条件晚到必须手点查询”“前端页大小与后端返回不一致”等问题。
- 统一弹窗内分页状态、最小 loading 展示时长、打开重置、依赖条件变化重载等通用逻辑，减少重复样板代码。
- 让搜索弹窗的分页规则与主列表分页规则保持一致：服务端分页只使用后端当前页数据，不与前端额外分页逻辑混用。

## 2. 背景

在本项目中，搜索弹窗大量分布于采购、销售、财务、系统管理等模块。虽然这些弹窗大多已接入服务端分页，但历史实现存在以下共性问题：

1. 每个弹窗都手写一套 `loading + page + pageSize + total` 状态。
2. 每个弹窗都手写 `setTimeout(200)` 作为 loading 缓冲。
3. 每个弹窗都手写“打开弹窗后重置筛选并加载数据”的逻辑。
4. 存在依赖 `supplierId`、`customerId`、`orgId`、`returnType` 的弹窗，在依赖值晚于弹窗打开时，首次请求拿不到数据。
5. 少数弹窗曾出现“服务端已分页后，前端再按客户或供应商过滤”的混用问题，导致 `total` 与当前页可见数据不一致。

对应的公共能力已沉淀在：

- [useRemoteDialogPagination.ts](file:///d:/WMS/Warehouse-Management/wms-vue3/src/composables/useRemoteDialogPagination.ts)

## 3. 适用范围

本规范适用于以下两类组件：

1. 标准搜索弹窗：命名通常为 `*SelectDialog.vue`
2. 选择器弹窗：命名通常为 `*Picker.vue`

本规范不适用于：

1. 非分页弹窗
2. 固定拉取特定数量、且不展示分页器的特殊弹窗
3. 纯本地静态列表弹窗

当前明确排除的特殊文件：

- [SalesReturnItemSelectDialog.vue](file:///d:/WMS/Warehouse-Management/wms-vue3/src/views/sales/SalesReturnItemSelectDialog.vue)
- [DeductionReceiptSelectDialog.vue](file:///d:/WMS/Warehouse-Management/wms-vue3/src/views/purchase/DeductionReceiptSelectDialog.vue)

说明：

- `SalesReturnItemSelectDialog.vue` 当前采用固定 `page: 1, page_size: 100` 的特殊模式，前端不展示标准分页器。
- `DeductionReceiptSelectDialog.vue` 当前不属于标准远程分页选择弹窗。

## 4. 统一规则

### 4.1 分页模式

搜索弹窗统一按“服务端分页”处理：

1. 请求参数必须显式传递 `page` 与 `page_size`
2. 表格直接渲染接口返回的当前页数据
3. 不允许在当前页结果上再次做前端分页切片

### 4.2 搜索行为

1. 点击“查询”时，必须先回到第一页，再触发加载
2. 点击“重置”时，必须清空筛选条件并回到第一页，再触发加载
3. 若接口采用 `search_field/search_value` 结构，优先复用 [data.ts](file:///d:/WMS/Warehouse-Management/wms-vue3/src/utils/data.ts) 中的 `buildSearchParams()`

### 4.3 打开行为

弹窗打开时统一执行以下动作：

1. 清空已选数据
2. 清空筛选条件
3. 重置页码到第一页
4. 触发首次加载

若弹窗还包含额外状态，如数量映射、价格映射、临时选中缓存等，也应在打开时一并重置。

### 4.4 依赖条件守卫

若弹窗依赖外部条件，如：

- `supplierId`
- `customerId`
- `orgId`
- `returnType`

则必须遵循以下规则：

1. 依赖条件未就绪时，不发请求
2. 依赖条件未就绪时，清空列表并清空总数
3. 依赖条件从空变为有效值时，自动重置页码并重载
4. 不在弹窗首次打开但依赖未就绪时弹出误导性 warning

### 4.5 Loading 规则

所有标准搜索弹窗统一保留最小 loading 展示时长：

```ts
withMinLoading(async () => {
  // request
})
```

默认最小时长为 `200ms`，用于避免数据返回过快时界面闪烁。

### 4.6 页大小规则

1. 标准弹窗使用 `pagination.pageSize` 与分页器双向绑定
2. 固定页大小的 `Picker` 必须显式传入固定 `PAGE_SIZE`
3. 前端显示的页大小必须与请求中的 `page_size` 完全一致

## 5. 公共实现

### 5.1 公共能力

已新增公共分页能力文件：

- [useRemoteDialogPagination.ts](file:///d:/WMS/Warehouse-Management/wms-vue3/src/composables/useRemoteDialogPagination.ts)

当前包含以下能力：

1. `useRemoteDialogPagination(initialPageSize = 20)`
2. `useDialogOpenReload(options)`
3. `useDialogDependencyReload(options)`

### 5.2 推荐接入方式

标准弹窗推荐使用以下结构：

```ts
const { loading, pagination, resetPage, clearPaginationTotal, withMinLoading } =
  useRemoteDialogPagination()

useDialogOpenReload({
  visible: () => props.modelValue,
  reset: () => {
    // reset filters / selected / temp state
    resetPage()
  },
  load: loadData,
})

useDialogDependencyReload({
  visible: () => props.modelValue,
  dependency: () => props.supplierId,
  isReady: (supplierId) => !!supplierId,
  reset: () => {
    resetPage()
  },
  load: loadData,
})
```

### 5.3 `loadData()` 推荐结构

```ts
async function loadData() {
  if (!props.supplierId) {
    list.value = []
    clearPaginationTotal()
    return
  }

  try {
    const res = await withMinLoading(() =>
      request({
        page: pagination.page,
        page_size: pagination.pageSize,
      })
    )
    list.value = res.data.items ?? []
    pagination.total = res.data.total ?? 0
  } catch {
    list.value = []
    pagination.total = 0
  }
}
```

## 7. 特殊说明

### 7.1 `PendingReturnSelectDialog` 的分页语义

[PendingReturnSelectDialog.vue](file:///d:/WMS/Warehouse-Management/wms-vue3/src/views/purchase/PendingReturnSelectDialog.vue) 当前会对接口返回的嵌套 `children` 做前端展平。这里的“展平”不属于再次前端分页，但需要注意：

1. 若后端按订单维度分页，而前端按明细维度展示，则一页可见行数可能超过 `page_size`
2. 当前 `total` 语义仍以后端返回为准

因此该文件虽然已接入统一分页能力，但后续若要进一步统一“明细页总数语义”，需要联动接口返回结构一起评估。

### 7.2 管理员弹窗的初始化

两个管理员弹窗在分页统一之外，还保留了各自的初始化逻辑：

1. 组织数据初始化
2. 岗位数据初始化
3. 角色数据初始化
4. 提交确认动作

这些业务初始化逻辑不归分页公共层管理，仍保留在各自组件内。

## 8. 验收标准

### 8.1 行为验收

- 弹窗打开后能自动加载首屏数据
- 查询和重置都会自动回到第一页
- 切换页码和页大小后，请求参数与 UI 一致
- 依赖条件晚到时，弹窗可自动补拉数据
- 依赖条件未就绪时，不出现误导性空请求或误提示

### 8.2 代码验收

- 标准搜索弹窗不再手写 `const minDelay = new Promise(...)`
- 标准搜索弹窗不再依赖 `@open="onOpen"` 单独维护初始化分页逻辑
- 搜索参数优先复用 `buildSearchParams()`
- 新增标准远程分页弹窗时，优先接入 [useRemoteDialogPagination.ts](file:///d:/WMS/Warehouse-Management/wms-vue3/src/composables/useRemoteDialogPagination.ts)

### 8.3 构建验收

- `GetDiagnostics` 无新增错误
- `npm run build` 通过

## 9. 后续约束

后续新增搜索弹窗时，默认按以下顺序实现：

1. 先判断是否属于标准远程分页弹窗
2. 若是，则优先接入 [useRemoteDialogPagination.ts](file:///d:/WMS/Warehouse-Management/wms-vue3/src/composables/useRemoteDialogPagination.ts)
3. 搜索参数优先使用 [data.ts](file:///d:/WMS/Warehouse-Management/wms-vue3/src/utils/data.ts) 的公共方法
4. 只有在明确属于“固定上限型”或“非分页型”场景时，才允许偏离本规范
