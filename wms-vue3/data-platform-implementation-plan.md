# 数据中台任务清单与实现方式

更新日期：2026-11-25

本清单用于将 WMS DataWorkspace 从前端演示逐步推进到可接入真实服务的产品。当前优先实现大文件分片上传和后台解析，解除前端固定 20MB 限制；同时保留服务端容量、账号配额和处理资源约束。

已完成通用文件处理链路第一版。后端接口、数据模型、任务和前端已接通；独立 Qdrant、Celery、生产 MySQL 与大文件压测仍待目标环境验证。下方原设计清单保留用于追踪剩余工作，未全部验收的任务不整体标记完成。

## 大文件上传与解析实施方案

### 目标流程

选择文件 → 创建上传会话 → 分片校验与上传 → 校验合并 → 创建后台解析任务 → 加载分页预览 → 配置分块 → 确认处理与入库。

“上传分片”是字节传输单元，“知识分块”是解析后的检索内容单元，两者采用独立参数和状态，不能混用。

### DP01 通用接口契约

- [ ] 确定支持的 PDF、DOCX、TXT、Markdown、XLSX、XLS、CSV 类型、文件校验规则和账号存储归属。
- [ ] 定义服务端能力接口，返回支持格式、直传阈值、分片大小、并发建议、文件上限和可用配额。
- [ ] 定义统一错误结构，区分文件不支持、容量不足、身份失效、分片损坏、会话过期和解析失败。
- [ ] 确定上传成功后的文件标识，以及上传会话、原文件、解析任务和知识文档之间的关联。

以下为原拟议契约。当前已实现接口见文首的后端说明，路径以 `/api/v1/knowledge/workspace` 为准；原清单保留供核对尚未落实的能力：

| 操作 | 拟议接口 | 关键输入与输出 |
| --- | --- | --- |
| 查询上传能力 | GET /api/v1/knowledge/uploads/capabilities | 返回格式、阈值、分片大小、配额及限制 |
| 初始化上传 | POST /api/v1/knowledge/uploads | 文件名、大小、类型；返回 upload_id、chunk_size、total_chunks、过期时间 |
| 上传分片 | PUT /api/v1/knowledge/uploads/{upload_id}/chunks/{index} | 分片内容、校验值；返回已接收状态 |
| 查询已上传分片 | GET /api/v1/knowledge/uploads/{upload_id} | 返回会话状态、已接收分片与后续操作所需信息 |
| 完成上传 | POST /api/v1/knowledge/uploads/{upload_id}/complete | 校验后返回稳定的 file_id；重复请求返回同一文件结果 |
| 取消上传 | DELETE /api/v1/knowledge/uploads/{upload_id} | 停止接收并回收该会话资源 |
| 创建解析任务 | POST /api/v1/knowledge/files/{file_id}/parse | 返回 parse_job_id；重复提交须防止产生重复任务 |
| 查询解析状态 | GET /api/v1/knowledge/parse-jobs/{parse_job_id} | 返回阶段、进度、失败原因与可重试状态 |
| 读取解析预览 | GET /api/v1/knowledge/files/{file_id}/preview | 按页、工作表、段落或游标返回有限量内容 |

### DP02 通用分片服务

- [ ] 复用现有 PDF 上传服务中的会话归属、分片落盘、校验、合并、幂等与过期回收设计。
- [ ] 为数据中台建立通用文件入口，不直接把 DOCX 或表格发往仅支持 PDF 的旧接口。
- [ ] 每片暂定 8MB，实际以服务端下发配置为准；校验分片序号、声明长度、实际长度及 SHA-256。
- [ ] 使用流式读写完成合并或对接对象存储分段上传，避免将整文件一次性读入内存。
- [ ] 合并后检查完整性与实际文件格式；对完成请求加并发保护，避免重复文件和重复存储占用。
- [ ] 为每次读写、完成、查询和取消操作验证账号归属；配额检查须计入正在上传的预留容量。
- [ ] 配置会话有效期、临时分片清理，以及完成上传但未被业务使用的孤立文件回收。

现有 Coze_Connect 的 `service/upload_chunk_service.py` 只接受 PDF。其代码默认每片 8MB、整文件上限 1GB，可作为设计参考；这些默认值不等于数据中台已经支持的容量，也不代表当前部署配置。

### DP03 前端上传管理

- [ ] 将“选择文件”和“读取完整正文”分离。选中文件后先展示名称、格式、大小和状态。
- [ ] 复用现有 `chunkedUpload.ts` 的回调注入、分片校验、并发与失败重试能力，并补齐通用文件适配。
- [ ] 默认考虑 3 至 4 个在途分片，由服务端配置和实际压测结果决定。
- [ ] 每次仅通过 File.slice 读取需要上传的片段，避免为上传计算而调用整文件 arrayBuffer。
- [ ] 小文件是否走直传由能力接口决定；第一阶段也可统一分片，减少两套链路的维护成本。
- [ ] 展示每个文件的上传进度、已传大小、速度、重试和取消状态；上传与解析进度分开显示。

### DP04 重试与断点续传

- [ ] 使用有上限的退避重试，并区分可重试网络错误与不可重试的类型、权限和配额错误。
- [ ] 取消操作终止在途请求，并通知服务端取消对应上传会话。
- [ ] 保存按账号隔离的上传会话标识；刷新后查询服务端已接收分片，只补传缺失部分。
- [ ] 刷新后若无法恢复本地 File 对象，明确提示重新选择原文件，并校验文件身份；不能只凭文件名和大小判定为同一文件。
- [ ] 单独处理会话过期、合并中、已完成和已取消状态，避免重复上传或重复创建解析任务。

现有前端上传器已有失败重试与 AbortSignal 取消能力，但尚未实现刷新后的断点续传。服务端已有上传状态查询能力，通用接口仍需确认和适配。

### DP05 后台解析与分页预览

- [ ] 上传完成后创建后台解析任务，根据文件类型选择解析器；PDF 的 OCR 需求单独判定。
- [ ] 为文档解析设置内存、耗时、页数、表格规模和压缩展开资源约束，并在错误结果中给出处理建议。
- [x] 预览支持内容块与图片分页（`block_offset`/`block_limit`、`image_offset`/`image_limit`）；全文超过 300,000 字符时改为 `text_complete=false` 并回退到分页块。剩余：服务端仍先读取完整解析 JSON 再切片，流式游标待补。
- [ ] 大文件先展示元信息和解析进度，解析可用后再显示预览；提供解析失败后的重试入口。
- [ ] 需要抽样试切片时明确显示抽样范围，避免把局部预览误认为整份资料的最终处理结果。

### DP06 限制与文案调整

- [ ] 在真实上传和后台解析可用后，移除当前 `fileParser.ts` 中固定的 20MB 拦截。
- [ ] 同步处理当前 30 万字符和每张表 5000 行的本地解析限制，改为后台处理约束和前端分页展示；不能只删除文件大小校验。
- [ ] 将上传区域说明改为服务端下发的实际能力，不写“无限大小”或无法兑现的格式支持。
- [ ] 配额不足、文件超限或服务暂不可用时，给出准确且可操作的提示。
- [ ] 接入真实服务前，保留模拟处理和会话内数据的必要说明；真实链路验收后再更新相关状态文案。

### 大文件链路验收标准

- [ ] 大于 20MB 的受支持文件能够完成真实上传、后台解析和预览。
- [ ] 上传重试只重传失败分片，刷新后重新选择原文件可以补传缺失分片。
- [ ] 分片内容被改动、缺失或乱序时能被识别；合并结果与原始文件一致。
- [ ] 重复完成请求不会生成多份文件，重试不会重复计费或重复占用账号配额。
- [ ] 取消上传后不再继续发送分片，残留临时数据按约定回收。
- [ ] 跨账号访问上传会话、文件和解析结果被后端拒绝。
- [ ] 文件上限、容量配额和不支持格式在前后端保持一致。
- [ ] 大文件上传期间前端只维持有限在途分片；预览按需加载，页面仍可正常操作。
- [ ] 对接近配置上限的文件、并发上传、解析失败、网络断开与会话过期场景进行验证，并记录实际资源占用。

## 后续生产化任务实现方式

### DP07 真实处理与入库

将当前本地分块配置转成可版本化的服务端参数契约。服务端校验参数并保存快照，后台执行解析结果清洗、分块、索引生成、向量化与写入。前端按任务阶段展示进度和可重试错误，文档详情使用对应版本的已保存结果，避免按最新配置重算后与入库内容不一致。模型兼容性、知识库模型约束及变更后的重建方式在接入前明确。

验收：页面显示真实任务结果，失败可定位到阶段；文档分块、参数快照和索引版本保持一致。

#### 图片识别与自动索引

- [x] 复用 Coze_Connect 的 `pdf_agent/llm.py` 视觉模型入口生成图片描述；在后台处理任务中调用。
- [x] PDF 图片引用保留页码、区域与哈希；DOCX、现代 Excel 的内嵌图片也可提取，旧表格图片和原生图表仍待适配。
- [x] 勾选“识别图片内容”会在后台生成描述，按图片哈希缓存，并与原图、来源和处理结果关联；任务进度、失败及重试可见。
- [x] 描述文本作为可检索内容进入现有文本 Embedding 与 Qdrant 集合，受账号、知识库和有效版本范围约束。
- [ ] 对复杂遮罩、重复图片的所有出现位置及部分图片失败做更充分的专项验收；纯图片/图文向量和以图搜图尚未接入。

这里的“图片索引”目前指**图片描述文字的索引与检索**；不代表已经建立图片向量或以图搜图能力。现有浏览器流程及隔离真实模型冒烟覆盖了开关触发、描述保存和文本检索，生产模型/队列仍需目标环境联调。

### DP08 记录持久化

按账号和知识库保存原文件引用、解析结果、参数快照、分块及任务状态。页面刷新后通过接口恢复列表和进行中的任务。数据库结构、数据保留周期与删除策略在实现时依据现有后端确认，不预设尚未存在的表。

验收：刷新或重新登录后仍能查询有权限的数据，进度和终态与服务端一致。

### DP09 账号与权限

复用 WMS 现有会话机制，通过真实身份显示名称及工作空间。后端按用户、组织和知识库校验读取、上传、处理、导出、删除权限；不能仅依靠前端隐藏按钮。完成对接后替换“演示用户”等占位内容。

验收：正确显示当前账号，不同账号间的上传、文件、任务和知识库记录隔离。

### DP10 联调与上线验证

按上传、解析、入库逐段联调，覆盖支持格式、超限、网络中断、刷新恢复、权限失效和部分失败。核对网关请求体及超时配置，避免分片上传仍被入口网关拦截。形成可复查的验收记录，再逐步替换模拟流程。

### DP11 待确认的体验增强与 DP12 配置简化

DP11 可借鉴 kb_hub 的宽预览布局、分块长度图、图表定位、标题路径、重叠区域标识和详情抽屉，具体范围待确认。DP12 已按用户要求简化为“带上文档标题”“提取内容摘要”“识别图片内容”三个选项，专业参数使用默认值，不再规划面向普通用户的高级参数面板。摘要和图片选项对应的真实后台处理纳入 DP07、DP15。

## 用户知识库管理与通用文档接入方案

实施方向：补齐用户知识库管理和通用文档入口，复用 Coze_Connect 现有的任务、向量化、图片索引、对象存储及检索能力。新增工作围绕数据中台的资料类型和知识库归属进行适配，保持既有官方产品知识库与 WMS 产品同步流程的行为。

### PDF 分流与图文处理

1. **文件检查**：校验真实格式、损坏、加密、页数及资源限制；无法处理时给出明确原因，不显示成功。
2. **逐页提取**：优先读取原生文字，提取嵌入图片及其出现位置；保留页码、版面顺序与标题线索。复用 service/pdf_service.py 的 PyMuPDF 提取能力。
3. **判断页面情况**：区分可直接读取文字的页面、扫描页和混合页面。判断依据结合文字覆盖、可读性及页面图像情况，不只看提取字数。
4. **补充正文识别**：扫描页或文字缺失的区域渲染为受控尺寸的图片，进行文字识别；复杂布局或识别质量不足时，按页或区域调用现有视觉模型补充。长页和超大图可分区处理，并保留坐标映射。
5. **识别有用图片**：用户开启“识别图片内容”后，处理照片、示意图、图表等有内容的区域。嵌入图片直接取图；由矢量图形等组成、无法通过嵌入图片提取获得的内容，评估通过页面或区域渲染补充。
6. **生成描述**：调用 pdf_agent/llm.py 的 vision_chat，结合图片及邻近正文生成客观描述、图片中文字及关键词；无法辨认的内容标记不确定，不补造参数、型号或数值。
7. **合并与去重**：按页面顺序组合正文、表格及图片关联。避免扫描整页文字同时作为正文和图片描述重复写入；保留原图与正文片段间的引用关系。
8. **预览与索引**：预览中可回到原页查看来源。用户确认后按统一默认规则生成知识块；图片描述按需要生成独立内容块，复用现有图片描述索引和媒体嵌入能力。

- [ ] 将以上步骤实现为可恢复的页级或资源级后台任务，记录成功、失败和跳过原因。
- [ ] 给扫描页、复杂排版、表格和矢量示意图准备实际样本，确认哪些走基础解析、哪些需要视觉模型。
- [ ] 依据文件哈希、页或图片哈希、解析器与模型提示词版本复用结果，避免只修改索引选项就重新识别整份文件。

当前通用资料入口是 `/api/v1/knowledge/workspace`：PDF 页面按原生文字、原生文字加表格或 VLM 分流；扫描页渲染 OCR，图片描述与预览、处理结果及文本索引关联。旧 `/pdf/parse` 属于另一条 PDF 接口。待补的是复杂页专项评估、模型/提示词缓存版本策略、图片来源的全部出现位置、按失败页精准重试及目标环境联调；现有扫描/图文/表格样本不能代替这些验收。
