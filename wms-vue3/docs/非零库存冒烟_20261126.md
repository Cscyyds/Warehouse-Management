仅创建标记为smk261126a8的两个产品、一个仓库、一个货位、两个位置、一个塑料盒、一个集散位。盒绑定到产品A所在位置，以验证位置汇总含盒时不会把盒余额重复加到产品总量。

## 未通过的小数数量预检

第一次准备单位字典时与已有“件”名称唯一约束冲突，事务整体回滚；随后只读复用已有单位，未改动原单位。

第二次以1.1250、2.3750、3.2501、4.7499、4.9999、0.0001等四位小数数量准备数据时，SQL出现Data truncated，库存组成校验抛出STOCK_RECONCILIATION_REQUIRED：位置汇总与条码、盒及无条码组成不一致。事务整体回滚，未留下该批余额。

这不是捕获到的HTTP接口报错，而是直接调用主工程库存业务原语时的实际数据库/业务校验失败。未宣称某个未调用的HTTP写接口已经返回此错误。

只读核对根因：

| 本地表/列 | 实际精度 | 当前模型精度 |
| --- | --- | --- |
| pms_product.available_stock / warehouse_stock | DECIMAL(18,2) | DECIMAL(18,4) |
| wms_product_position.stock_qty | DECIMAL(18,2) | DECIMAL(18,4) |
| wms_plastic_box.box_stock_qty | DECIMAL(18,2) | DECIMAL(18,4) |
| wms_distribution_spot_stock.stock_qty | DECIMAL(18,2) | DECIMAL(18,4) |
| wms_simple_stock_balance.stock_qty | DECIMAL(18,4) | DECIMAL(18,4) |

汇总列和余额列精度不同，写入后无法保持一致。本轮未擅自ALTER现有库存列。之后改用整数数量完成其余非零读取验证；四位小数写入场景仍为未通过。

## 清理和恢复

finally清理仅按上述隔离产品/对象的明确ID和租户执行：删除7条测试库存流水、8条余额（含零余额）、1条集散位产品汇总、1个盒、2个位置、1个集散位、1个货位、1个仓库、2个产品及本轮新建的1条单位。原有单位保留，测试开关审计保留。

最终开关恢复0；测试余额剩余0。原有产品available_stock/warehouse_stock按产品ID排序后的SHA256测试前后相同：55715f109eb9670f84099d5c9bf1b8db8979baff21283e67a3048d03e5e0a434。

结论：三类存放、多长度、整数非零库存的真实页面读取链路通过；四位小数写入因本地历史表精度未对齐而未通过，不能视为完整全量验收通过。
