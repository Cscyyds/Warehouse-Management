# 产品库存：普通与简易模式字段差异及存放对象展示

依据：当前本机主工程tenant_wms_management.py、simple_stock_queries.py，以及PDA stock-info和简易Excel导出实现。不能把不同接口的字段混作同一份JSON。

## 同一Web接口下的差异

| 范围 | 普通模式 | 简易模式 |
| --- | --- | --- |
| GET /api/v1/tenant-inventory/products | data.list，产品基础字段；available_stock/warehouse_stock为原库存口径，stock_amount为原仓库库存×成本价 | data.list基础字段名相同，两个库存数量改为正数无条码余额合计，金额按该合计×成本价；simple_stocks携带该产品正余额 |
| GET /api/v1/tenant-inventory/search | data.products，原跨产品/条码/位置搜索 | data.products，按产品资料及无条码存放对象搜索；库存数值/排序切换为余额口径，不是新增一套表头目录 |
| GET /api/v1/tenant-inventory/products/detail | barcodes[]及其positions[]，散件/塑料盒/合包/集散位条码合计 | barcodes为空，原四类条码合计为0；真实库存明细在simple_stocks[]，不能把原合计0当作无库存 |

产品基础字段包括product_id/product_code/item_no/product_name/category_name/specification/color/unit_name/avg_cost_price/stock_warning_qty/available_stock/warehouse_stock/stock_amount（以各列表投影为准）。现有JSON没有动态columns或headers目录。列表和搜索的数据数组键也不同，不可混读。

## 明细表头应不同

普通明细使用barcode_type_label、barcode_code、barcode_name、cut_length，以及positions中的warehouse_name、location_no/location_name、floor_no/position_no、position_code、last_inbound_time、stock_qty。

简易明细使用place_type、可读存放对象字段、length_mm、stock_qty、updated_at，按balance_id标识一行。按余额直接求和一次，不把包含盒的父位置汇总再加到盒余额上。

## 本批确认并补充的主工程字段

用户确认：主工程详情补齐名称/编号，前端沿用原接口，不额外调用PDA stock-info。

主工程simple_stocks新增可空字段：

| 类型 | 中文名称来源 | 编号来源 |
| --- | --- | --- |
| POSITION | location_name + floor_no层 + position_no号位 | position_code，缺省时可用location_no |
| PLASTIC_BOX | box_name | box_code |
| DISTRIBUTION_SPOT | spot_name | spot_no |

place_id仍作为内部关联字段保留，不在页面列、tooltip或名称缺失时回退展示。中文名和编号都缺失时显示“未提供名称或编号”。盒名缺失不能拿父位置编号冒充盒编号。

后端按当前租户、实际ID、有效资料批量查询；缺失、失效、跨租户或产品归属失配的资料返回null，余额本身保留，数量/长度/合计不变。列表里的simple_stocks复用同一投影；接口路径、请求、权限和余额结构不变。

前端库存明细标题保留“返回 / 库存明细 / 产品编码”，移除截图框选的产品名称。

## 另外两种接口

PDA GET /api/v1/tenant-wms/products/stock-info的stock.simple_stocks有自己的一套位置扩展资料，bound_positions还含直接/盒内余额分项；它与Web库存接口的层级、权限不同，前端本批未切换来源。

POST /api/v1/tenant-products/positions/export输出XLSX，简易模式确实使用不同表头（20列，含存放类型、编码、名称、长度、无条码数量），普通模式走原位置模板。Excel表头不是Web JSON的动态表头。
