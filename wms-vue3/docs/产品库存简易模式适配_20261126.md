# 产品库存简易模式：后端梳理与前端适配

## 依据与范围

依据后端合并 `96db949`，其中 `dcabff7` 引入库存查询口径切换及相关测试；核对了 `docs/待执行结构变更.sql`、`docs/本日接口变更.md` 的历史更正和当前实际实现。

本轮只适配 Web 产品库存列表、搜索、库存明细和库存导出文案。库存分析、分类库存浏览的库存与金额由后端自动切换，现有前端读取字段无需新增计算。未新增无单放货、扫码操作或租户模式开关。

## 后端权威规则

- `sys_tenant.simple_mode_enabled=1` 时，只统计 `wms_simple_stock_balance` 正余额（B）。列表 `available_stock`、`warehouse_stock` 取B合计，`stock_amount` 取B×成本价；排序也使用B。前端不可把B再次叠加到这些总量上。
- 无余额产品仍保留在产品列表和分页中，数量为0。
- 普通模式继续使用原库存字段和条码明细；`simple_stocks=[]`。
- 简易模式详情 `barcodes=[]`，散件、塑料盒、货位合包、集散位四种条码合计均为0；实际无条码库存放在 `simple_stocks`。这些0不能作为无库存的结论。
- 原接口路径、请求参数、权限保持。普通/简易切换由后端决定，不传客户端 mode 参数。

| 主工程接口 | 前端处理 |
| --- | --- |
| GET /api/v1/tenant-inventory/products | 读取 list 和后端库存字段；接入 simple_stocks 类型，简易模式数量保留返回精度 |
| GET /api/v1/tenant-inventory/search | 读取 products；简易搜索文案不再承诺条码匹配；过滤和排序留给后端 |
| GET /api/v1/tenant-inventory/products/detail | 分开展示无条码余额与普通条码明细 |
| GET /api/v1/tenant-inventory/analysis | 原字段和结构保持，后端已切换统计口径 |
| GET /api/v1/tenant-inventory/category-analysis | 同上 |
| GET /api/v1/tenant-inventory/category-browse | 同上 |
| POST /api/v1/tenant-products/positions/export | 保持JSON请求和Blob下载，后端自动选择普通或简易模板；简易页面不再显示“含空位”导出选项 |

## 主工程实际余额字段

`balance_id`、`product_id`、`place_type`、`place_id`、`length_mm`、`stock_qty`、`version`、`updated_at`，以及后端附加的 `length_status`。其他审计字段不展示。

`place_type` 为 POSITION、PLASTIC_BOX、DISTRIBUTION_SPOT。主工程当前 `stock_rows` 只返回对象ID，不附加对象编码/名称。因此Web展示“存放对象 ID”，不把ID伪装成编码，也不额外请求没有授权的档案接口。扫码端 `/tenant-wms/products/stock-info` 的位置名称、盒名称等扩展字段属于另一响应，不混用到本接口。

长度始终标为毫米；0表示无长度，显示“-”。数量按字符串和BigInt保留四位精度；长度保留六位精度。不经过浮点数计算。缺失或受限数量显示“-”，任何一行数量不可见时不展示可反推的完整合计。

## 模式和会话

实时状态来源为扫码后端 `GET /api/v1/tenant-wms/simple-mode/status`，使用 `VITE_SCANNER_API_BASE_URL` 配置及当前员工令牌。产品库存列表和详情每次加载、刷新、keep-alive重新激活时重新查询；`data.simple_mode_enabled` 为权威布尔值。状态查询失败显示重试提示，状态保持未知，不把失败默认为关闭，不因独立扫码服务401清掉主站会话。

已取得实时状态时，开启展示无条码明细，关闭展示条码明细，与登录时状态无关。状态不可用时，只按接口返回的真实明细展示；两种明细均为空时显示“暂无库存明细”，不猜测模式。

登录响应 `simple_mode_enabled` 仍随WMS会话槽保存和切换，退出或换租户时清理，PDF独立账号不继承WMS模式；它不再作为库存页面实时模式的判断来源。
