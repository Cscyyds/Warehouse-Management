# 知识库构建流程学习与数据中台适配方案（产品资料 / 安装说明 / 百问百答）

整理日期：2026-11-24（v2）

本文依据 CSDN「企业级知识库与智能问答实战系列」第 1–5 篇整理完整知识库流程，并针对我们知识库的真实内容——**产品资料、安装说明、百问百答**——重写清洗、结构化与切片策略，逐项对照数据中台现状给出适配方案。

> 来源：第 1/2/3/4/5 篇均已读到全文（第 4 篇按用户提供的登录态补读）。原系列面向规章制度类文档，其"条款切片"只适用于合同/制度分支；本文把可迁移的原则（清洗步骤、结构锚点、标签/元数据、切片粒度、检索过滤）落到三类产品内容上。

## 一、系列文章给出的通用流程（保留可迁移部分）

```text
📄 采集 → 🧹 清洗 → ✂️ 切片与结构提取 → 🏷️ 标签与元数据
→ 🤖 向量化 → 📦 向量库 → 🔎 相似度检索 → 🧠 RAG 问答
```

**可迁移的通用原则**：

1. **清洗三步法**：结构识别（标题层级/编号/统一标识作为锚点）→ 剔除无用页（封面、目录、修订记录、水印）→ 正文清洗（保留结构化内容，统一乱码/单位）。
2. **切片目标**：每片是"最小可用问答单元"——语义完整、**Token < 512**、保留上下文结构；过长无法入上下文，过短语义不完整。
3. **元数据与向量同存**：`document / section / tag / page_num` 随向量写入，支撑过滤、权限、业务线隔离与 UI 展示。
4. **标签先行**：可枚举、多维、字典化；规则打标优先，LLM 打标辅助；检索时先过滤再召回（`k=5`）。
5. **RAG 组装**：命中 3~5 条拼 Prompt，**拼接上下文建议 ≤ 1500 tokens**。
6. **格式工具**：Word→python-docx；PDF→PyMuPDF/pdfplumber；扫描→OCR（原文推荐 PaddleOCR/EasyOCR，我们已用 VLM）；Markdown→校验标题层级。

**不可直接迁移的部分**：原文的"按条款（第X条）切片"是为制度手册设计的。我们的产品资料没有"第X条"，锚点完全不同（见第二节）。

第 4 篇补充细节（全文已读）：
- Embedding：bge-base-zh / text2vec / 通义 / GLM；HF 示例为 mean pooling；
- 向量库选型：FAISS（元数据过滤需扩展）、Milvus、Weaviate、Zilliz Cloud、Pinecone；
- 元数据示例：`{document, chapter, tag[], page_num}` 与 `embedding` 同条存储；
- 检索：`similarity_search(query, filter={"tag": ...}, k=5)`；
- 进阶：多段拼接后送模型，`context = "\n\n".join(top_chunks)`。

## 二、三类内容的清洗 / 结构化 / 切片方案（核心）

### 2.1 内容形态与锚点总览

| 内容类型 | 典型文件 | 结构锚点 | 推荐切片单元 | 元数据重点 |
| --- | --- | --- | --- | --- |
| 产品资料 | 规格表（xlsx/csv）、产品图册（pdf）、参数页 | 表头列名、产品编码/型号、规格族分组 | **一行 = 一条记录**；同型号参数组合一块 | 产品编码、名称、型号/规格、材质、类目、工作表、行号 |
| 安装说明 | 安装手册（pdf/docx）、图文步骤 | 章节（第一章/一、）、步骤编号（1./①/步骤X）、警告标记、图注 | **最小可执行步骤组**（同小节连续步骤 ≤500 字） | 章节路径、步骤号范围、页码、图号、警告级别 |
| 百问百答 | FAQ（md/txt/表格）、客服问答 | `## 问题？` 标题、`问：/答：`、`Q:/A:` | **一问一答为一块**（不拆） | 问题原文、分类（标题路径）、同义问法 |

### 2.2 产品资料

**清洗**
- 去封面、目录、修订记录、页脚说明（通用规则）；
- 保留全部规格表网格；**跨页重复表头合并**（同一列名序列重复出现时只保留一次）；
- 统一单位与符号（mm/cm、kg/g、±、°），全角/半角统一；
- 同产品重复规格表去重（同产品编码 + 同参数集合只保留一份，保留页码来源）；
- 纯营销话术段落可配置剔除（默认保留，避免误删卖点描述）。

**结构化提取**
- 识别规格表：表头行（如 `产品编码 | 产品名称 | 规格 | 材质 | 表面处理 | 单价`）；
- 合并单元格向下继承（类目/系列列）；
- 每行输出一条记录，表头随记录保存（`origin.headers`）；
- 产品名 + 型号/规格 作为记录主键描述，缺失时用文件名兜底。

**切片**
- 每行一个块（现规则整行 ≤6000 字符不拆，超长报错提示拆分）；
- 索引前缀：`产品名称 / 型号规格 / 列名摘要`（现有 `titleIndex` 语义不变）；
- 参数组场景（同产品多行参数）：按产品聚合为一块，行间用 `；` 连接，块内保留表头一次。

**元数据**
- `product_code`、`product_name`、`model/spec`、`category`、`sheet`、`row`；
- 与官方产品库对齐时，可映射 `official_product_id` / `variant model_code`（对齐 `product_knowledge` 的"型号级技术参数块"模式：`型号：{code}` + 参数清单）。

**示例（按我们样例数据）**

```text
原文行：HG-4寸不锈钢合页 | 不锈钢合页 | 4寸×3寸×3.0mm | 304 不锈钢 | 拉丝 | 38
索引前缀：产品资料 / 不锈钢合页 / 4寸×3寸×3.0mm / 产品编码、材质、表面处理、单价
块正文：产品编码 HG-4寸不锈钢合页；产品名称 不锈钢合页；规格 4寸×3寸×3.0mm；材质 304 不锈钢；表面处理 拉丝；单价 38 元
```

**验收问法**： "4 寸 3.0mm 的不锈钢合页多少钱？" → 命中该行块，回答含规格与单价。

### 2.3 安装说明

**清洗**
- 去封面、目录、修订记录、免责声明页；
- 保留**安全警告**（"警告""注意""⚠"），并把警告挂到它约束的后续步骤（不单独成块漂移）；
- 保留图注（"图 3 合页定位示意"），图片与所属章节/步骤关联；
- 去页眉页脚重复行（连续页首尾重复短文本）。

**结构化提取**
- 章节路径（第一章 / 一、）→ `heading_path`；
- 步骤序列：`1.` `2.` `①` `步骤 1` 等，提取步骤号；
- 前置条件：工具清单、配件清单、开箱检查（归入"准备"类）；
- 参数值（180mm、950～1050mm、扭矩、4 颗螺钉）**不拆散、不改写**；
- 图片（示意图/装配图）与步骤关联，开启图片识别时生成描述并与步骤同块。

**切片**
- 以"最小可执行步骤组"为单位：同一小节内连续步骤合并，≤500 字符；
- 块前缀：`章节路径 + 步骤号范围`（如 `第二章 合页安装 / 第 1–2 步`）；
- 警告块与其约束步骤同块，保证检索到步骤即带安全要求；
- 跨小节不合并（避免"定位+固定"混在一起答非所问）。

**元数据**
- `section`、`heading_path`、`step_range`、`page`、`figures[]`、`warning_level`。

**示例（按我们样例数据）**

```text
块：第二章 合页安装 / 定位
上合页距门顶 180 mm，下合页距门底 250 mm，门高超过 2.2 米时在中间加装一片合页。
用水平尺确保三片合页轴心在同一垂线上。
```

**验收问法**： "上合页离门顶多少？" → 命中"定位"块，答案 180 mm，引用章节与页码。

### 2.4 百问百答（FAQ）

**清洗**
- 统一问答标记：`## 问题？`、`问：/答：`、`Q:/A:`、表格两列（问题|答案）；
- 去空行、广告、联系方式、重复分隔线；
- **同义问题合并**：保留主问法 + `aliases`（如"退货要什么材料" ≈ "客户退货需要哪些材料"），避免同一答案被多次召回。

**结构化提取**
- QA 对：`question`、`answer`、`category`（由标题路径或 FAQ 分组得出）、`aliases[]`；
- 答案中的步骤/条件（"2 个工作日内完成验收"）保持完整。

**切片**
- **一问一答为一块**，即使答案较长也不拆（>6000 字符报错提示拆分）；
- 索引前缀 = 问题原文（可附分类）；答案作为正文；
- 同一问题的多个追问（"能当天冲减吗？"）独立成块，不并入主答案。

**元数据**
- `q`、`category`、`aliases`、`source`；
- 标签建议：分类（售后/物流/退换货/安装）由标题或规则打标。

**验收问法**： "退货多久能入库？" → 命中对应 QA 块；同义问法（"退货验收要多久"）也能命中。

### 2.5 三类之外：合同/制度（兼容分支）

保留原文的条款锚点策略（第X章/第X条），仅在识别到合同、制度类文档时启用；不作为默认路径。

### 2.6 内容类型识别（默认策略选择）

| 信号 | 判定 |
| --- | --- |
| 表格行占比高、表头含"编码/名称/规格/材质/单价" | 产品资料 |
| 存在步骤编号 + 章节 + 工具/配件清单、大量图注 | 安装说明 |
| 标题为疑问句占比高、存在 `问/答` 标记 | 百问百答 |
| 出现"第X条/第X章"且为条文式段落 | 合同/制度 |
| 无法判定 | 通用段落策略（现有 500 字 + 50 重叠兜底） |

判定结果写入处理参数快照（`content_type`），前端默认 `auto`，可在专业设置里覆盖（普通用户不可见）。

## 四、与现有前端的适配方案

### 4.1 前端现状

- 用户只有三个开关：**带上文档标题 / 提取内容摘要 / 识别图片内容**（DP12，保持不变）；
- 知识库按名称文本创建/复用；`/libraries` 已实现但未接入；
- 预览分「原始数据 / 分块预览」；分块卡片显示文本、索引、字符区间；
- `processing.ts` 保留完整切片配置（策略/大小/重叠/分隔符），UI 已简化；
- kb-hub demo 已有 `storeMode = chunk | whole | qa`（qa = 按标题生成问答对），可作为 FAQ 模式的前端契约参考。

### 4.2 适配原则

1. 三开关不变；**内容类型自动识别**，策略后台生效，不新增普通用户开关；
2. 处理参数快照新增 `content_type`（auto/product/manual/faq/policy）与 `store_mode`，随任务版本保存；
3. 所有清洗删改进入 `warnings` 并在预览可见，不静默丢内容；
4. 策略变更升 `parser_version` / `index_version`，旧结果不重算。

### 4.3 分阶段实施

#### P0：服务端按类型增强（前端零改动）

**状态：已实现 v1（2026-11-24），26 项后端测试通过。** 解析器版本升级为 `workspace-reader-v2`，处理版本 `workspace-processor-v2`。

| 改动 | 位置 | 状态 | 说明 |
| --- | --- | --- | --- |

#### P2：标签与过滤检索 —— ⚠️ v1 已落地（2026-11-24）

已经实现：用户自定义标签（维度轴 domain/category/custom，取值由用户创建、企业内共享）、动态建议（按用户标签名/keywords 匹配，无固定分类规则）、文档级标签与检索过滤（`/search` 的 `tag_ids`）、标签变更不重算向量、前端动态选择/新建/建议与检索筛选。
剩余：字典管理页（改名/合并/停用）、历史 `category` 迁移、知识库默认标签、批量归类、审计；行级产品属性过滤属第二期。

- 知识库级标签字典（产品类目/安装章节/FAQ 分类），文档级 tags 覆盖；
- 规则打标：规格表用类目/材质列，安装说明用章节名，FAQ 用标题分类；LLM 建议作为补充；
- payload 增加 `tags` 并建索引；`/search` 支持 `tags` 过滤；
- 前端：文档详情标签编辑 + 检索面板标签筛选。

#### P3：基于知识库的问答（RAG）

- `POST /chat`：`/search`（k=5）→ 拼接（≤1500 tokens，按第 4 篇建议）→ LLM 流式回答，返回引用（document/page/section/行号）；
- 前端知识库详情增加「问答」页签，答案下展示引用卡片，可跳转预览；
- 优先覆盖"售后百问百答 + 安装说明"场景（用户高频问题）。

### 4.4 参数建议

| 参数 | 建议值 | 依据 |
| --- | --- | --- |
| 通用块大小/重叠 | 500 字符 / 50 | 现状，中文 ≈350–750 token |
| FAQ 块 | 一问一答整块，不设上限（>6000 报错） | 语义完整优先 |
| 安装步骤组 | ≤500 字符，同小节合并 | 可执行性 + 上下文 |
| 产品记录 | 一行一块 | 精确检索数值 |
| 检索 top-k | 5 | 第 4 篇示例 |
| RAG 上下文 | ≤1500 tokens | 第 4 篇明确建议 |
| 索引前缀 | 标题路径/问题/产品型号（`titleIndex` 语义） | 现状 + 类型适配 |

## 五、实施顺序与风险

**顺序**：P0 清洗与类型化切片 → P1 知识库前端 → P2 标签过滤 → P3 问答。

**风险与边界**
- 类型识别可能误判（混合文档）：保留"通用段落"兜底，warnings 标注判定依据；
- 步骤/问答识别依赖排版：扫描件 OCR 后编号可能丢失，需按"章节标题 + 段落"退化处理；
- 产品表头合并需谨慎：列名不一致（"单价" vs "单价（元）"）按归一化后比较；
- 同义问题合并涉及语义判断，先做规则（去标点/去"请问"），LLM 合并作为人工确认项；
- 图片与步骤关联依赖解析器图注提取，不保证全部可关联，缺失时仅存页码；
- 第 4 篇为短篇，向量化参数建议以实测召回为准。
